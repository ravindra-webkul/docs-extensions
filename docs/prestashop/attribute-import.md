# Attribute Import

The attribute import job pulls attributes from PrestaShop into UnoPim. It imports two types: **Features** (descriptive product attributes) and **Variant Options** (attributes used in product combinations).

---

## How to Run

1. Go to **Data Transfer → Imports → Create Import**.

!["Data Transfer"](./assets/import/data-transfer-import.png)

!["Create Import Job"](./assets/import/create%20import.png)

2. Select type **Prestashop Attributes**.

!["Prestashop Attributes"](./assets/import/attribute-import.png)

3. Set the filters:

| Filter | What to pick |
|---|---|
| **Prestashop Credential** | Your PrestaShop connection (only enabled credentials are listed) - required |
| **Channel** | The UnoPim channel mapped to the shop you import from - required |
| **Locales** | The locales to import, from those mapped for the channel - required |

4. Save and run the job.

!["Job Log"](./assets/import/save-run-attribute.png)

## Two Types Imported

| PrestaShop Type | What it is | Created in UnoPim as |
|---|---|---|
| **Feature** | A product feature (e.g. Material, Color) | A `select` type attribute |
| **Variant Option Group** | A combination attribute (e.g. Size, Color) | A `select` type attribute |

Both types import their options/values along with the parent attribute.

> Custom feature values (entered per product in PrestaShop) are not imported by this job - only predefined values become options. To bring custom values into UnoPim, create a **text** attribute, add it to *Attributes to be used as feature attribute (For Export)* in the Other Mapping tab, and run [Attribute Export](./attribute-export.md) once so the attribute is linked to the PrestaShop feature. Product imports then write each product's custom value into that text attribute.

---

## What Gets Imported Per Attribute

- **Attribute code** - slugified from the name (e.g. "Material" → `material`)
- **Attribute name** - localized per language
- **All options** - each with its own code and localized labels

If the attribute already exists in UnoPim (same code), it is **updated** as a select attribute. Otherwise it is **created**:

| Imported from | Created in UnoPim as |
|---|---|
| Feature | Select attribute, value per locale |
| Product option group | Select attribute, not per locale or channel, so it can be used as a variant attribute |

Imported attributes are not added to any attribute family. Add them to the family you select in the product import jobs.

> **Note:** If UnoPim already has an attribute of another type (for example a text attribute) with the same code as a PrestaShop feature, it is changed to a select attribute. Use a different code for text attributes that you export as features.

---

## Variant Attributes for Product Import

When product options are imported, the connector remembers which UnoPim attribute each PrestaShop option group became. The configurable and variant product imports use these records to decide which attributes define the variants, so run **Attribute Import** before importing configurable products or variants.

---

## Code Generation

If the PrestaShop feature or option group was not imported before, the attribute code is generated by slugifying its PrestaShop name in the default locale (spaces → underscores, lowercase, up to 50 characters). Example: "Shoe Size" → `shoe_size`. If the name is empty, `feature_{id}` or `product_option_{id}` is used.

On re-import, the connector matches by PrestaShop ID so existing attributes are updated without duplicates.

---

## Localization

Attribute names and option labels are imported for each selected locale using the credential's **Shop Mapping** (PrestaShop language ID → UnoPim locale code).

If the default locale has no name, the name from another locale is used for it.

---

## Common Issues

| Issue | Fix |
|---|---|
| Attributes not appearing in UnoPim | Check the job log for API errors; verify the credential has permission to read features |
| Wrong attribute code generated | Codes come from the PrestaShop name - rename it in PrestaShop before the first import |
| Option labels missing | Make sure the selected locales are mapped in the credential's Shop Mapping |
| Duplicate attributes created | Re-imports match by PrestaShop ID - check the data mapping table for stale records |
| *"No features (attributes) found in PrestaShop."* | The store has no features, or the key has no GET permission on `product_features` |
| *"No product option groups (variant attributes) found in PrestaShop."* | The store has no product options, or the key has no GET permission on `product_options` |
| *"Variant attribute '…' is scoped per-locale/channel and can't be used as a variant axis."* | Recreate the attribute as global (not per locale, not per channel) |
| Imported attributes missing on products | Add the attributes to the attribute family used by the product import |
